# Executor brief: read this before every task

You are completing **one task card** from `docs/TASKS.md` for DEADWEIGHT, a first-person
physics movement game made with Godot 4.7.2 (GDScript, Jolt physics) that is being finished
for Steam (Windows/Linux, Steam Deck) and Google Play (Android). Read only:

1. this brief,
2. your task card in `docs/TASKS.md` (and the board row to see dependencies),
3. the `docs/CONTRACT.md` sections your card cites (APIs, data shapes, budgets),
4. the files your card lists under **Read** and **Edit**.

Don't read the whole repository. `docs/DESIGN.md` is the product spec, so look things up there.

## Environment

- Windows 11, PowerShell 5.1. Project root: the folder that contains `project.godot`.
- Godot binary: `.tools/godot/Godot_v4.7.2-stable_win64_console.exe` (run from the root).
- **Quality gate (run before you finish):** `powershell -ExecutionPolicy Bypass -File tests/run_all.ps1`
  It parse-checks every `.gd` file and runs every `tests/*_test.gd` suite. To run just one suite:
  `... tests/run_all.ps1 -Only physics_test -NoParse`.
- **Parse-check one file:** `<godot> --headless --path . --check-only --script res://path/file.gd`
- **Run one suite:** `<godot> --headless --fixed-fps 90 --path . --script res://tests/<name>.gd`
- **Rendered captures (no window on screen):** add `--position 20000,20000 --resolution 1280x720`.
  Use `--rendering-method gl_compatibility` to preview the mobile renderer. Save PNGs under
  `.tools/captures/<task-id>/` and **look at them**. If you can't view images, say so in your report.
- **Run the game:** `powershell -ExecutionPolicy Bypass -File tools/run.ps1` (`-Touch` for touch UI).

## Rules

1. **Do only your task.** Edit only files listed under **Edit** (you may create the new files it
   names). If something outside your files blocks you, stop and report it under *Blockers*.
   Don't patch it silently.
2. **Keep the game runnable.** The quality gate must pass when you finish. Never leave
   half-wired code that the main scene loads.
3. **Code style:** typed GDScript, tabs, no `class_name` (load scripts with `preload("res://...")`),
   short functions, comments that explain intent. Models, animation and audio are generated by
   code. Raster textures are allowed only under `assets/dreamscape/`, each with its exact prompt
   in `assets/dreamscape/PROMPTS.md`. Don't download assets, fonts or plugins unless the card
   explicitly says so.
   **Visual direction:** "The Department of Unfinished Gravity" (`docs/DREAMSCAPE.md`, CONTRACT §8).
   It is an absurdist dreamscape of porcelain, chalk, plum, dusty rose, brass and celadon under a
   painted sky. Red still means danger, cyan route and rod information, amber actions and salvage.
   Reuse `scripts/dreamscape.gd` and `scripts/dream_props.gd`. Don't add new raw-metal or grimy
   industrial looks.
4. **Contract APIs are binding.** If your card makes you change a public API, update
   `docs/CONTRACT.md` and every caller in the same task, and mention it in your report.
5. **Never touch the player's real save.** Pass `--profile=user://<task-id>.cfg` to the game or
   use a temp path in tests.
6. Don't run exports, imports or the editor unless your card says so.
7. Test what you build: add the tests your card names. Prefer real-physics checks over mocks.

## Definition of done

- Every acceptance check in your card passes, and `tests/run_all.ps1` prints `QUALITY GATE: PASSED`.
- In `docs/TASKS.md`, set your task's board **Status** to `done (YYYY-MM-DD)`.
- Append an entry to `docs/PROGRESS.md` with: the date, the task id, the model that did it,
  the files changed, test results, any deviations, and follow-ups.
- If the repo uses git, commit with the message `Txx: <title>`.
